# 松序 Breezith

> 顺气舒心，慢养日常 —— 面向年轻人的中医「轻养生」Web 应用

在线演示：<https://songxu-breezy.xin>

松序把疏肝解郁、节气饮食、穴位保健、功法带练这些传统养生方法，拆解成每天可以真正做一遍的小事：今天该喝什么茶、按哪个穴、穿多厚、几点睡、跟练一遍八段锦。核心是用**端侧 AI 判断你有没有做对**，把「看视频自己练」变成「有人盯着你练」。

---

## 一、项目简介

当代年轻人的健康困扰往往不是「病」，而是「说不上哪里不舒服」：熬夜后乏力、久坐后颈肩僵、换季时情绪低落。中医对此有一套完整的日常调养方法，但门槛在于——普通人不知道怎么选、怎么吃、按哪里、动作对不对。

松序用三件事降低这个门槛：

1. **节气 + 天气 + 体质的联动推荐**：根据 IP 定位与实时天气，结合用户自测的九种体质，给出当天的饮食、穿衣、起居、穴位建议，而不是一份静态的养生文章。
2. **端侧 AI 功法跟练**：八段锦十式做动作时，浏览器本地实时识别 33 个身体关键点，判断手位、肘角、膝角、脚宽、重心、头偏等，逐式计次、扣分、达标自动出分。**视频帧不上传任何服务器**。
3. **大模型养生助手**：接入 DeepSeek，配合中医知识库与工具调用，回答「我最近总口苦该吃什么」这类开放式问题，并给出可执行的三餐、穴位、作息方案。

## 四、AI 技术方案

### 4.1 端侧姿态评测（八段锦十式）

**为什么放在端侧**：跟练场景需要摄像头持续输入，若上传服务器推理，既有延迟也有隐私风险。MediaPipe 的 WASM 版本可在普通笔记本/手机上跑到可用帧率，因此选择**纯前端推理，视频与图像帧不出浏览器**。

**关键点与指标**：Pose 模型输出 33 个身体关键点，Hands 模型补充手部 21×2 点。由此计算：

- 腕相对肩的高度、手在身前程度（z 差）、双手间距、手到髋/踝的距离
- 肘角、膝角（三点夹角）
- 踝距/脚宽比、髋到踝高度、髋到脚尖高度
- 躯干侧倾角、前倾量、重心左右偏移、头部左右偏转

**归一化基准的取舍**：最初用肩宽作分母，实测发现侧向伸展与转身时肩宽在 2D 投影下会骤缩到原来的 1/5，导致所有比值虚高。改为除以**躯干长**（肩中 → 髋中）后稳定。但俯身动作时躯干本身也会缩短，这属于真实姿态而非检测失败，因此在判据上**不再用比值类指标做硬门禁**，只信角度类指标。

**计次引擎**：每式一个状态机，由「进入阈值 + 退出阈值 + 最短间隔 + 保持时长」四要素驱动（迟滞计次），避免在阈值边界反复抖动造成重复计数。例：

- 射雕：手距 > 0.85 且一臂肘角 > 130° 进入，手距 < 0.60 退出
- 摆尾：侧倾 ≥ 12° 保持 1s 计次，回中 ≤ 6° 持续 1s 才允许下一次
- 攀足：三阶段（上举 → 俯身触脚 → 起身），触脚瞬间计次
- 七颠：提踵时踝骨随髋一起升高，髋高几乎不变，改用**脚尖（不离地）**作基线，滚动 2s 取最低值 + 0.05 判定抬起

**阈值校准方法**：以 `?posebug=1` 测量模式导出逐帧指标（0.25~0.5s 一帧），按「自己执行标准动作」的采样数据分布确定阈值，再用同一份数据逐帧回放验证计次结果与真实动作节奏是否一致。十式全部完成此流程。

**诚实的降级策略**：正对镜头是线上真实使用视角，但某些指标在该视角下不可靠——例如冲拳正对镜头时手臂 2D 投影被压扁，肘角读数最高仅 116°。这类指标一律**只提示、不扣分**，扣分只施加于确证的指标（屈膝、双手不同步、转头幅度不足、侧摆不足、提踵不足）。

### 4.2 大模型养生助手

- `server/agent/orchestrator.js` 负责对话编排：注入体质档案、当日节气与天气，决定是否调用工具
- `server/agent/tools/index.js` 提供穴位、体质、饮食、节气等查询工具，让模型基于结构化知识库作答而非自由发挥
- `server/agent/providers/deepseek.js` 封装模型调用与流式返回
- `server/agent/safety.js` 做输入输出安全兜底（拒绝诊断类、用药剂量类越界请求，引导就医）
- `server/agent/chatStore.js` 维护会话上下文（MySQL 持久化，未连库时降级内存模式）

### 4.3 创新点

**技术创新**
1. 端侧（浏览器内）中医功法姿态评测，零上传、零服务端算力成本
2. 用躯干长归一化 + 「不可靠指标不参与扣分」的判据降级机制，解决单目 2D 视角下的投影失真问题
3. 迟滞式计次引擎，适配不同体质/节奏用户的动作速度差异
4. 以实测采样数据反推阈值并逐帧回放验证的校准流程，而非凭经验设参

**应用创新**
1. 「节气 + 天气 + 体质」三输入驱动的当日建议，把养生从知识变成日程
2. 把八段锦从「看视频跟练」升级为「可评分、可计次、自动结束」的闭环训练
3. 功法、饮食、穴位、情绪工具共用同一份体质档案，形成个人化养生档案

## 六、快速开始

### 环境要求

| 依赖 | 版本 |
|---|---|
| Node.js | ≥ 18 |
| MySQL | ≥ 8.0 |
| 浏览器 | 支持 WebGL / WASM 的现代浏览器（Chrome / Edge / Safari 新版） |

### 步骤

```bash
# 1. 安装依赖
npm install

# 2. 下载 AI 跟练所需的 MediaPipe 模型（约 26MB，未纳入 Git）
npm run models

# 3. 配置环境变量
cp .env.example .env
# 编辑 .env，填入 DeepSeek API Key、MySQL 密码、JWT 密钥、高德 Key

# 4. 初始化数据库（建库、建表、写入种子数据，可重复执行）
npm run init-db

# 5. 启动
npm start
```

启动后访问 <http://localhost:3100>。

> `public/ai-models/` 体积约 26MB（MediaPipe 运行时、WASM 与两个模型文件），未纳入 Git 仓库。
> `npm run models` 会从 jsDelivr 与 MediaPipe 官方源固定版本下载；重复执行会跳过已存在的文件。
> 不执行该步骤时，其他功能正常，仅 AI 跟练不可用。

### 环境变量

全部项见 [.env.example](.env.example)，关键项：

| 变量 | 说明 |
|---|---|
| `PORT` / `HOST` | 监听端口与地址（生产环境 `HOST` 填 `127.0.0.1`，仅允许 Nginx 本机反代） |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` | 大模型接入 |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | MySQL 连接 |
| `JWT_SECRET` / `JWT_EXPIRES` | 认证签名与有效期 |
| `AMAP_KEY` / `AMAP_DEFAULT_ADCODE` / `AMAP_DEFAULT_CITY` | 高德 IP 定位与天气 |
| `MEMORY_TURNS` | 对话携带的历史消息条数 |

> `JWT_SECRET` 请务必使用随机值生成：
> `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

### 无数据库运行

未配置或连接不上 MySQL 时，服务会自动降级为**内存存储模式**，功能可体验（重启后数据丢失），便于评审快速试跑。

## 七、部署

生产环境为阿里云 ECS + Nginx：

- Nginx 负责 HTTPS 终结与反向代理到 `127.0.0.1:3100`（须与 `.env` 的 `PORT` 一致）
- Node 进程由进程管理器常驻，`HOST` 绑定本机回环地址，不对公网暴露 3100 端口
- 静态资源由 Express 提供，图片/JS/CSS 带版本号（`?v=`）配合 7 天缓存
- MediaPipe 模型与 WASM 自托管于 `public/ai-models/`，不依赖第三方 CDN

## 八、安全与隐私

- 所有密钥通过环境变量注入，`.env` 已加入 `.gitignore`，仓库内仅保留 `.env.example`
- 姿态识别的视频帧**全部在浏览器本地推理，不上传**
- 静态服务仅开放 `public/` 目录，不暴露 `server/` 源码与 `package.json`
- 接口鉴权使用 JWT，敏感接口强制登录
